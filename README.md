## Описание проекта

Система предназначена для автоматизированного учёта проб, выполнения расчётов по методам исследования, формирования протоколов испытаний и управления лабораторной документацией. Приложение позволяет отслеживать жизненный цикл проб от поступления в лабораторию до формирования итоговых протоколов, автоматически выполнять расчёты по заданным формулам и генерировать протоколы в формате .xlsx на основе шаблонов.

### Основная функциональность

**Управление пробами:**
- Регистрация проб с регистрационными номерами, уникальными в рамках лаборатории и подразделения
- Учёт типа пробы и объекта испытаний; перечень объектов ведётся в справочнике (теги связывают объект с применимостью методов)
- Привязка проб к лабораториям, подразделениям, филиалам и местам отбора
- Указание условий отбора проб (давление, температура и другие параметры)
- Указание дат отбора и получения проб в лабораторию
- Указание объекта испытаний, скважины, режима работы скважины
- Выбор объекта испытаний из справочника с учётом области видимости (лаборатория и подразделение)
- Указание количества показателей (используется при формировании отчёта «Количество проб»)

**Методы исследования:**
- Управление методами исследования с настраиваемыми формулами расчёта
- Поддержка различных типов округления (десятичное, значащие цифры, табличное, кратное)
- Определение условий повторяемости (удовлетворительная, неудовлетворительная, отсутствие, следы, кастомные значения)
- Настройка погрешности измерения (фиксированная или по формуле)
- Группировка методов исследования для отображения в протоколах
- Привязка методов к лабораториям и подразделениям
- Указание типов проб, для которых применим метод
- Указание приборов по умолчанию для метода
- Настройка порядка сортировки методов
- Особая обработка методов "Массовая доля нефти" и "Фракционный состав"
- Версионирование при редактировании: старая запись помечается удалённой, создаётся новая с тем же наименованием; сохранённые расчёты остаются привязаны к id старой версии

**Расчёты:**
- Выполнение расчётов по методам исследования с использованием входных данных
- Автоматическое вычисление промежуточных результатов по заданным формулам
- Проверка условий повторяемости перед расчётом основного результата
- Автоматическое округление результатов по заданным правилам
- Вычисление погрешности измерения (фиксированной или по формуле)
- Обработка пустых значений (замена на '0' для числовых расчётов)
- Особая обработка метода "Массовая доля нефти": автоматический расчёт C1 и C2 по показателям преломления n1 и n2 через таблицу преломления
- Особая обработка фракционного состава: расчёт множественных результатов для различных температур и процентов отгона
- Привязка расчётов к пробам, методам исследования, лабораториям и подразделениям
- Указание исполнителя расчёта (по hsnils)
- Указание даты проведения лабораторного исследования
- Привязка используемого оборудования к расчёту
- Уникальность расчёта: один метод исследования может быть применён к одной пробе только один раз (с учётом только неудалённых записей)
- Редактирование расчёта: сохранение новой версии записи (предыдущая помечается удалённой), а не изменение на месте
- При редактировании, если методика в справочнике обновлена, выбор — по правилам на момент сохранения расчёта или по актуальной версии с тем же наименованием

**Протоколы:**
- Создание протоколов испытаний с привязкой к пробам
- Указание номера и даты протокола испытаний
- Указание признака аккредитации протокола
- Указание номера акта отбора
- Указание лиц, оформивших и утвердивших протокол (по hsnils)
- Указание должностей оформившего и утвердившего
- Генерация протоколов в формате .xlsx на основе шаблонов
- Автоматическая подстановка данных из проб, расчётов и оборудования в шаблон
- Обработка меток в шаблоне для подстановки значений (номера протокола, даты, места отбора, условий отбора, исполнителей и др.)
- Автоматическое формирование таблиц с методами исследования, оборудованием и нормативными документами
- Группировка методов исследования в протоколе
- Особая обработка фракционного состава для отображения в таблице 1 протокола
- Автоматическое разбиение протокола на страницы при превышении размера листа
- Поддержка множественных листов в протоколе
- Автоматическое формирование колонтитулов с номером протокола и нумерацией страниц
- Скрытие строк шаблона при отсутствии данных (например, условий отбора)
- Обработка аккредитационной шапки (скрытие для неаккредитованных протоколов)

**Оборудование:**
- Учёт приборов и оборудования с указанием типа (измерительный прибор, испытательное оборудование)
- Указание наименования, серийного номера, сведений о поверке
- Указание дат поверки и окончания срока действия поверки
- Указание версии прибора
- Привязка оборудования к лабораториям и подразделениям
- Использование оборудования в расчётах

**Лаборатории и организационная структура:**
- Управление лабораториями с указанием аббревиатуры, полного названия и места осуществления деятельности
- Управление подразделениями лабораторий с указанием названия и места осуществления деятельности
- Создание и удаление лабораторий и подразделений — только admin; редактирование карточек и настройки (шаблоны, условия отбора) — при праве `laboratory_management`
- Управление филиалами с указанием названия и телефона
- Управление местами отбора проб с привязкой к филиалам
- Управление режимами работы скважин с привязкой к филиалам
- Иерархическая структура: Лаборатория -> Подразделение -> Филиал -> Место отбора проб

**Условия отбора проб:**
- Настройка шаблонов условий отбора для лабораторий и подразделений
- Определение структуры условий отбора (название переменной, единица измерения)
- Хранение значений условий отбора в пробах
- Использование условий отбора при генерации протоколов

**Справочники:**

*Шаблоны протоколов:*
- Управление шаблонами протоколов (.xlsx файлы в формате base64 или пути к файлам)
- Указание версии шаблона
- Указание строки аккредитационной шапки для скрытия при неаккредитованных протоколах
- Привязка шаблонов к лабораториям и подразделениям

*Градуировочный график:*
- Страница «Градуировочный график» (`/refraction-tables`) с drill-down по лаборатории и подразделению
- Список методов «Массовая доля нефти» в выбранной области; редактирование таблицы преломления в модальном окне
- Управление таблицей преломления: соответствия между массовой долей нефти (C) и показателем преломления (n)
- Связь таблицы преломления с методом исследования
- CRUD и видимость вкладки настраиваются правами `refraction_tables`

*Объекты испытаний:*
- Справочник наименований объектов испытаний с уникальным тегом (связь с типами проб в методах исследования)
- Область видимости: привязка к лабораториям и подразделениям; пустая область означает доступность везде
- CRUD через API и страницу «Объекты испытаний» (поиск, сортировка, пагинация)
- Использование в формах проб (выпадающий список по лаборатории/подразделению) и при создании методов исследования (типы проб)
- Определение тега типа пробы по наименованию объекта при подборе методов исследования к пробе

*Нормы НД:*
- Справочник текстов норм по методам исследования для объекта испытаний
- Привязка к лаборатории и подразделению; наименование нормы и объект испытаний
- Хранение текстов по методам в JSON (`method_data`: id метода и текст нормы)
- Страница «Нормы НД» с drill-down по лаборатории и подразделению (аналогично пробам, приборам и градуировочному графику)

*Роли и права доступа:*
- Справочник ролей с типом (`laborant`, `engineer`) и списком привязок `scopes`: каждая привязка — `laboratory_id`, опционально `department_id` и своя матрица прав `permissions`
- Пустой список привязок означает отсутствие доступа (кроме admin); привязка только к лаборатории даёт доступ ко всем её подразделениям
- Страница «Роли» для ведения каталога; права настраиваются на `/roles/:id/permissions` — выбор лабораторий/подразделений и матрица прав для активной привязки
- Настраиваются: видимость вкладок, CRUD по справочникам (протоколы, приборы, места отбора, нормы НД, градуировочный график), поля и действия с пробами, расчёты, доступ к управлению лабораториями, терминология «режим скважины» / «точки отбора»
- Права текущего пользователя: `GET /user-roles/me/` (роли из токена `access_groups.appRoleName`; при совпадении ключа lab/dept у нескольких ролей флаги объединяются по OR; `permissions` в ответе — объединение по всем привязкам для навигации без контекста; admin — полный доступ)
- Права разных лабораторий внутри одной роли независимы: доступ к разделу в лаборатории A не открывает тот же раздел в лаборатории B
- Enforcement на UI и API с учётом текущей лаборатории/подразделения (карточки, кнопки, гарды страниц → 403; проверки в эндпоинтах)

*Шаблоны отчётов:*
- Хранение шаблонов отчётов (.xlsx в base64) по типам: «Количество проб», «Физико-химическая характеристика», «Результаты КГС», «Результаты НКС»
- Привязка к лаборатории и подразделению, версионирование, мягкое удаление
- Загрузка и редактирование шаблонов (а также шаблона протокола и условий отбора) из меню настроек карточек в «Управление лабораториями»

**Формирование отчётов (лаборатория ИЛНиНМ):**
- Доступно только для лаборатории с названием «ИЛНиНМ» (проверка на backend и отображение кнопки на frontend)
- Кнопка «Сформировать отчёт» на странице «Поступления проб»: выбор типа отчёта и периода, скачивание файла
- Вся логика сборки данных и заполнения .xlsx на backend (`services/ilninm_reports/`)

| Тип отчёта | Период по | Результат |
|------------|-----------|-----------|
| Количество проб | Дата получения пробы | ZIP: .xlsx + текстовый файл; разбивка по филиалам |
| Физико-химическая характеристика | Дата отбора | .xlsx; цех ЦДГГКН №1 или №2, объект «нефть» |
| Результаты КГС | Дата отбора | .xlsx; паспортизация, дегазированный конденсат |
| Результаты НКС | Дата отбора | .xlsx; нефтеконденсатная смесь |

- **Количество проб:** для каждого филиала копируется блок шаблона (столбец A — branch, B — категории, C — данные). Категории: товарная/эксплуатационная/калибровочная нефть (НГДУ/УГПУ), паспортизация, ГКП-21/ГКП-22, ОИС, прочие, дизтопливо, ингибитор коррозии и др.; пустые строки не выводятся; учитывается поле `indicators_count` у пробы
- **Физико-химическая характеристика:** пробы с местом отбора ЦДГГКН, расчёты по методам нефти (плотность, вязкость, фракционный состав и т.д.)
- **Результаты КГС / НКС:** выборка проб и подстановка результатов расчётов в фиксированные столбцы шаблона; группировка КГС по месту отбора

**Фикстуры методов исследования:**
- Хранение типовых описаний методов в формате JSON
- Организация по лабораториям и каталогам: `ilninm/26th/`, `ilninm/non-typical/`, `ilninm/nspk/` и др.
- Использование в UI создания метода как справочник (prefill полей), без автоматической загрузки в БД

**Дополнительные функции:**
- Интеграция с HR API для получения данных о сотрудниках
- Поиск сотрудников по ФИО и лаборатории
- Получение данных сотрудника по hsnils
- Получение должности и ФИО сотрудника на конкретную дату
- Кэширование данных сотрудников для оптимизации запросов
- Мягкое удаление записей (soft delete) для сохранения истории

## Архитектура проекта

Проект построен по принципу разделения на frontend и backend части с использованием современного стека технологий.

**База данных:**
- PostgreSQL с поддержкой схем
- Миграции через Alembic
- Асинхронная работа через SQLAlchemy 2.0
- Мягкое удаление записей (soft delete) через поле deleted_at
- Уникальные индексы с учётом soft delete

**Аутентификация:**
- Keycloak для единой аутентификации
- JWT токены для авторизации запросов
- Middleware для проверки токенов и извлечения информации о пользователе

**Интеграции:**
- HR API - получение данных о сотрудниках по ФИО или hsnils, получение должностей на конкретную дату

### Backend (FastAPI + Python)

**Технологии:**
- FastAPI для создания REST API
- SQLAlchemy 2.0 для работы с базой данных (асинхронный режим)
- Alembic для миграций базы данных
- Pydantic для валидации данных и настроек
- Uvicorn как ASGI сервер
- Pendulum для работы с датами
- ORJSON для быстрой сериализации JSON
- OpenPyXL для работы с .xlsx файлами (генерация протоколов и отчётов ИЛНиНМ)
- HTTPX для асинхронных HTTP запросов к внешним API
- Loguru для структурированного логирования

### Frontend (React + TypeScript)

**Технологии:**
- React 19 с TypeScript
- Vite 7 для сборки
- React Router 7 для навигации
- TanStack Query (React Query) для серверного состояния и кэширования
- Zustand для клиентского состояния
- Ant Design 5 для UI компонентов
- TanStack Table для сложных таблиц
- Keycloak JS для аутентификации
- Axios для HTTP запросов
- Day.js для работы с датами на frontend
- dnd-kit для drag-and-drop сортировки методов в админке

**Стилизация:**
- Парные CSS-файлы рядом с компонентами (без CSS modules)
- Готовые UI компоненты из Ant Design (формы, модальные окна, уведомления)
- Иконки: React Icons и обёртки в `shared/ui/icons`
- Кастомные компоненты с современными эффектами

**Архитектура Frontend:**
- Feature-Sliced Design (FSD) для организации кода
- Слои: app, pages, widgets, features, entities, shared
- Страницы — тонкие оболочки (маршрут, проверка прав, виджет); логика экрана — в widgets
- HTTP-клиенты и типы сущностей — в `entities/*/api`; аутентификация и права с сетью — в `app`
- Разделение логики и представления; проверка границ FSD через Steiger

## Логика работы системы

### Жизненный цикл пробы

1. **Регистрация пробы:**
   - Создание записи о пробе с регистрационным номером
   - Указание типа пробы и объекта испытаний (из справочника с учётом области видимости)
   - Привязка к лаборатории и подразделению
   - Опционально: указание филиала и места отбора
   - Указание дат отбора и получения
   - Указание условий отбора (давление, температура и др.)
   - Указание скважины и режима работы

2. **Выполнение расчётов:**
   - Выбор метода исследования для пробы
   - Ввод входных данных согласно структуре метода
   - Автоматический расчёт промежуточных результатов по формулам
   - Проверка условий повторяемости
   - Если условия не выполнены (отсутствие, следы, неудовлетворительная) - возврат соответствующего результата без расчёта основного значения
   - Если условия выполнены - расчёт основного результата по формуле метода
   - Автоматическое округление результата
   - Вычисление погрешности измерения
   - Сохранение расчёта с указанием исполнителя и даты проведения исследования
   - Привязка используемого оборудования

2.1. **Редактирование расчёта:**
   - Сохраняется новая версия записи; предыдущая помечается удалённой
   - Если методика в справочнике обновлена с момента сохранения, пользователь выбирает: редактировать по старым правилам (id из расчёта) или по актуальной версии с тем же наименованием
   - Сохранённый в БД результат не пересчитывается автоматически при смене методики в справочнике

3. **Специальные методы расчёта:**

   **Массовая доля нефти:**
   - При вводе показателя преломления n1 автоматически рассчитывается массовая доля C1 через таблицу преломления
   - При вводе показателя преломления n2 автоматически рассчитывается массовая доля C2 через таблицу преломления
   - Используется интерполяция между ближайшими значениями в таблице
   - Рассчитанные значения C1 и C2 используются в дальнейших расчётах

   **Фракционный состав (конденсат):**
   - Расчёт множественных результатов для различных процентов отгона (5%, 10%, 20% и т.д.)
   - Расчёт температуры начала кипения (н.к.) и конца кипения (к.к.)
   - Расчёт объёмных долей отгона, остатка и потерь
   - Специальное форматирование для отображения в протоколе

   **Фракционный состав (нефть):**
   - Расчёт множественных результатов для различных температур (100°C, 120°C, 150°C и т.д.)
   - Расчёт температуры начала кипения (н.к.)
   - Специальное форматирование для отображения в протоколе

4. **Формирование протокола:**
   - Создание протокола с указанием номера, даты, признака аккредитации
   - Привязка проб к протоколу
   - Указание лиц, оформивших и утвердивших протокол
   - Выбор шаблона протокола (.xlsx файл)
   - Генерация протокола на основе шаблона:
     - Обработка шапки протокола с подстановкой меток
     - Формирование таблицы с методами исследования и результатами
     - Группировка методов исследования, если они входят в группу
     - Особая обработка фракционного состава для отображения всех результатов
     - Формирование таблицы с используемым оборудованием
     - Формирование таблицы с нормативными документами
     - Обработка исполнителей и подписантов протокола
     - Автоматическое разбиение на страницы
     - Формирование колонтитулов с номером протокола и нумерацией страниц

### Логика расчётов

**Обработка входных данных:**
- Пустые значения автоматически заменяются на '0' для числовых расчётов
- Исключение поля "Цвет" из переменных для вычисления формул (это строка)

**Вычисление промежуточных результатов:**
- Последовательное вычисление промежуточных результатов по заданным формулам
- Использование ранее вычисленных промежуточных результатов в последующих формулах
- Поддержка различных типов округления промежуточных результатов:
  - Десятичное округление до заданного количества знаков
  - Округление до кратного значения
  - Табличное округление (выбор значения на основе сравнения с целевой переменной)
- Поддержка диапазонных расчётов для промежуточных данных
- Опция скрытия промежуточных результатов в итоговом ответе (show_calculation)

**Проверка условий повторяемости:**
- Последовательная проверка всех условий повторяемости
- Приоритет условий: кастомное значение > отсутствие > следы > неудовлетворительно > удовлетворительно
- Если выполнено условие "отсутствие", "следы", "неудовлетворительно" или кастомное значение - возврат соответствующего результата без расчёта основного значения
- Если выполнено условие "удовлетворительно" - продолжение расчёта основного результата
- Сохранение информации только о выбранном условии с шагами расчёта

**Вычисление основного результата:**
- Вычисление по формуле метода исследования
- Использование всех входных и промежуточных данных
- Округление результата по заданным правилам:
  - Десятичное округление до заданного количества знаков после запятой
  - Округление до значащих цифр
- Вычисление погрешности измерения:
  - Фиксированная погрешность из конфигурации метода
  - Погрешность по формуле с использованием результата и других переменных
- Округление погрешности до того же количества знаков после запятой, что и результат

**Особая обработка формул:**
- Поддержка математических функций: abs, pow, round, max, min
- Замена символов умножения (×) и деления (÷) на стандартные (* и /)
- Обработка подстрочных индексов в формулах (например, n₁, C₂)
- Безопасное выполнение формул без доступа к встроенным функциям Python

**Погрешность и пустая конфигурация метода:**
- Если в методе `measurement_error` задан как пустой объект `{}`, погрешность в расчёте не вычисляется
- Аналогично пустые `{}` для `intermediate_data` и `convergence_conditions` означают отсутствие промежуточных шагов и проверок повторяемости

### Версионирование записей

**Методики исследования:**
- Редактирование в UI создаёт новую запись; старая помечается удалённой, имя методики сохраняется
- Расчёты, сохранённые ранее, ссылаются на id старой версии и при пересчёте могут использовать её правила
- Актуальная версия определяется по наименованию в рамках лаборатории и подразделения

**Расчёты:**
- Изменение сохранённого расчёта — через создание новой записи с soft delete предыдущей
- Уникальность пары «проба + метод» проверяется только среди неудалённых расчётов

**Оборудование:**
- При изменении данных прибора создаётся новая версия (vN+1), старая запись помечается удалённой
- Ссылки на приборы в расчётах сохраняют привязку к конкретной версии

### Генерация протоколов

**Обработка шаблона:**
- Загрузка шаблона .xlsx из базы данных (base64 или путь к файлу)
- Поиск меток в шаблоне для подстановки значений
- Обработка специальных меток:
  - `{{start_header}}` и `{{end_header}}` - границы шапки протокола
  - `{{start_table1}}`, `{{start_table2}}`, `{{start_table3}}` - начало таблиц
  - `{end_table1}`, `{end_table2}`, `{end_table3}` - конец таблиц
  - Метки данных: `{test_protocol_number}`, `{sampling_date}`, `{registration_number}` и др.
  - Метки условий отбора: `{sel_cond_name_1}`, `{sel_cond_value_1}`, `{sel_cond_unit_1}` и др.
  - Метки таблицы методов: `{id_method}`, `{name_method}`, `{result}`, `{measurement_error}`, `{unit}`, `{measurement_method}`
  - Метки оборудования: `{id_equipment}`, `{name_equipment}`, `{serial_num}`, `{ver_info}`, `{ver_date}`, `{ver_end_date}`
  - Метки НД: `{id_nd}`, `{nd_code}`, `{nd_name}`
  - Метка исполнителя: `{executor}`

**Обработка шапки протокола:**
- Копирование строк шаблона между `{{start_header}}` и `{{end_header}}`
- Подстановка значений меток из протокола и проб
- Обработка условий отбора с подстановкой значений из проб
- Скрытие строк, если условия отбора отсутствуют (метка `{sel_cond_*}`)
- Скрытие аккредитационной шапки для неаккредитованных протоколов

**Формирование таблицы методов исследования:**
- Сбор всех расчётов по привязанным пробам
- Фильтрация методов по объекту испытаний (тип пробы по тегу из справочника или эвристике по наименованию)
- Группировка методов исследования:
  - Методы, входящие в группу, отображаются вместе с общим названием группы
  - Методы с особыми названиями (содержащими "нефть" или "конденсат") отображаются как одиночные, даже если входят в группу
- Особая обработка фракционного состава:
  - Фракционный состав конденсата: отображение всех результатов в виде подстрок с названиями полей
  - Фракционный состав нефти: отображение всех результатов в виде подстрок с названиями полей
- Нумерация методов в протоколе
- Копирование стилей из шаблона
- Автоматическое разбиение таблицы на страницы при превышении размера

**Формирование таблицы оборудования:**
- Сбор уникального оборудования из всех расчётов по привязанным пробам
- Сортировка оборудования по наименованию и версии
- Формирование таблицы с данными оборудования
- Автоматическое разбиение таблицы на страницы при превышении размера

**Формирование таблицы нормативных документов:**
- Сбор уникальных нормативных документов из методов исследования
- Фильтрация по объекту испытаний
- Формирование таблицы с шифром и наименованием НД
- Автоматическое разбиение таблицы на страницы при превышении размера

**Обработка исполнителей протокола:**
- Копирование строк после последней таблицы
- Подстановка значений меток
- Обработка метки `{executor}` с отображением всех уникальных исполнителей расчётов
- Автоматическое разбиение на страницы

**Формирование колонтитулов:**
- Обработка меток `{test_protocol_number}`, `{str}`, `{strs}` в колонтитулах
- Формирование номера протокола с учётом аккредитации (добавление суффикса `/07/{suffix}`)
- Добавление даты протокола к номеру
- Нумерация страниц с указанием общего количества страниц

**Управление страницами:**
- Автоматическое создание новых листов при превышении высоты страницы A4
- Сохранение стилей и форматирования при копировании на новый лист
- Настройка полей страницы (левое 1.5 см, правое 1.0 см, верхнее 1.1 см, нижнее 0.9 см)
- Подгонка по ширине страницы
- Нумерация листов: "Лист 1", "Лист 2" и т.д.

### Справочник объектов испытаний

1. **Ведение каталога:** наименование, тег (например `oil`, `condensate`), область видимости по лабораториям и подразделениям.
2. **Использование в пробах:** в формах создания и редактирования пробы список объектов фильтруется по выбранной лаборатории и подразделению.
3. **Связь с методами:** при создании метода исследования типы проб выбираются из тегов доступных объектов; при подборе методов к пробе тег определяется по наименованию объекта в справочнике (с запасной эвристикой по тексту, если записи в каталоге нет).

### Формирование отчётов (ИЛНиНМ)

1. Администратор загружает шаблон .xlsx нужного типа для лаборатории (и при необходимости подразделения).
2. Пользователь на «Поступлениях проб» выбирает тип отчёта и период (дата получения или отбора в зависимости от типа).
3. Backend выбирает актуальный шаблон, загружает пробы и расчёты за период, применяет правила категоризации (`ilninm_reports`), заполняет шаблон и отдаёт файл (или ZIP для «Количество проб»).

### Работа с фикстурами методов исследования

**Структура фикстур:**
- Фикстуры хранятся в директории `backend/research_methods_fixtures/`
- Организация по лабораториям: `{lab_name}/{catalog}/`
- Примеры: `ilninm/26th/`, `ilninm/non-typical/`, `ilninm/nspk/`
- Каждая фикстура — JSON-файл с описанием метода исследования

**Использование в приложении:**
- API отдаёт дерево каталогов фикстур и содержимое выбранного файла
- Доступно дерево уже сохранённых в БД методов по лаборатории (для копирования настроек)
- При создании метода в разделе администрирования выбранная фикстура **подставляет поля формы** (prefill)
- Сохранение в базу выполняет администратор вручную; автоматического импорта всех фикстур нет

### Интеграция с внешними системами

**HR API:**
- Поиск сотрудников по ФИО (минимум 3 символа) с фильтрацией по лаборатории
- Получение данных сотрудника по hsnils
- Получение должности и ФИО сотрудника на конкретную дату (с учётом истории назначений)
- Батч-запросы для получения данных о нескольких сотрудниках одновременно
- Кэширование результатов для оптимизации повторных запросов
- Форматирование ФИО в формат "И.О. Фамилия"

## Команды

### Миграции базы данных

Из директории `backend/` (с активированным venv). Схема PostgreSQL берётся из `POSTGRES_DB_SCHEMA` в `.env`.

```bash
alembic upgrade head
```
**Описание:** Применяет все неприменённые миграции к базе данных, доводя схему до актуального состояния (до версии "head").

```bash
alembic revision --autogenerate -m "краткое_описание"
```
**Описание:** Сравнивает модели SQLAlchemy с текущей БД и создаёт файл миграции в `alembic/versions/`. Autogenerate учитывает только схему из `POSTGRES_DB_SCHEMA` (чужие схемы в той же БД не трогает). В сгенерированном файле имя схемы подставляется через `SCHEMA = get_database_schema()` (шаблон `alembic/script.py.mako` и post-write hook `alembic_rewrite_schema`), а не хардкодом.

Перед применением всегда проверьте diff миграции вручную: autogenerate может пропустить переименования, данные и часть ограничений.
### Проверки backend

Из директории `backend/` (с активированным venv):

```bash
python check.py
python check.py --fix
```
**Описание:** Ruff format/check, basedpyright и import-linter (контракты слоёв `api → services → repositories → models`). Флаг `--fix` применяет автоформат и автоисправления Ruff перед проверками.

## Структура данных

### Основные сущности

**Sample (Проба):**
- Хранит информацию о пробе с регистрационным номером
- Привязана к лаборатории, подразделению, филиалу, месту отбора
- Содержит тип пробы, объект испытаний, даты отбора и получения
- Хранит условия отбора в формате JSON
- Поле `indicators_count` — количество показателей (для отчётов ИЛНиНМ)
- Связана с расчётами, выполненными по пробе
- Уникальность регистрационного номера в рамках лаборатории и подразделения (с учётом только неудалённых записей)

**Calculation (Расчёт):**
- Хранит входные данные и итоговый результат расчёта
- Привязан к пробе, методу исследования, лаборатории и подразделению
- Содержит информацию об исполнителе (hsnils) и дате проведения исследования
- Хранит погрешность измерения и единицу измерения
- Содержит список ID используемого оборудования
- Уникальность: один метод исследования может быть применён к одной пробе только один раз среди неудалённых записей
- При редактировании создаётся новая запись, предыдущая помечается удалённой

**ResearchMethod (Метод исследования):**
- Хранит название метода, формулу расчёта, структуру входных и промежуточных данных
- Содержит настройки округления (тип и количество знаков)
- Определяет условия повторяемости (или пустой объект `{}`, если проверки не нужны)
- Хранит погрешность измерения (фиксированную, формулу или `{}` при отсутствии погрешности)
- Указывает единицу измерения результата
- Содержит информацию о методе измерения, шифре и наименовании НД
- Определяет типы проб, для которых применим метод
- Может входить в группы методов исследования
- Привязан к лаборатории и подразделению
- Имеет порядок сортировки
- При редактировании в UI заменяется новой записью (soft delete старой версии)

**ResearchMethodGroup (Группа методов исследования):**
- Хранит название группы и порядок сортировки
- Связывает несколько методов исследования для группового отображения в протоколах

**Protocol (Протокол):**
- Хранит номер и дату протокола испытаний
- Содержит признак аккредитации
- Хранит номер акта отбора
- Содержит hsnils лиц, оформивших и утвердивших протокол
- Содержит должности оформившего и утвердившего
- Привязан к лаборатории, подразделению и шаблону протокола
- Содержит массив ID привязанных проб

**ProtocolTemplate (Шаблон протокола):**
- Хранит название и версию шаблона
- Содержит .xlsx файл в формате base64 или путь к файлу
- Указывает строку аккредитационной шапки
- Привязан к лаборатории и подразделению

**Equipment (Оборудование):**
- Хранит тип оборудования (измерительный прибор, испытательное оборудование)
- Содержит наименование, серийный номер, сведения о поверке
- Хранит даты поверки и окончания срока действия поверки
- Содержит версию прибора (v1, v2, …); при изменении создаётся новая запись
- Привязан к лаборатории и подразделению

**Laboratory (Лаборатория):**
- Хранит аббревиатуру, полное название и место осуществления деятельности
- Связана с подразделениями, филиалами, пробами, протоколами, расчётами, оборудованием, методами исследования
- Уникальность аббревиатуры (с учётом только неудалённых записей)

**Department (Подразделение):**
- Хранит название и место осуществления деятельности
- Привязано к лаборатории
- Связано с филиалами, пробами, протоколами, расчётами, оборудованием, методами исследования
- Уникальность названия в рамках лаборатории (с учётом только неудалённых записей)

**Branch (Филиал):**
- Хранит название и телефон филиала
- Привязан к лаборатории и подразделению
- Связан с местами отбора проб, режимами работы скважин и пробами

**SamplingLocation (Место отбора проб):**
- Хранит название места отбора пробы
- Привязано к филиалу
- Связано с пробами
- Уникальность названия в рамках филиала (с учётом только неудалённых записей)

**WellMode (Режим работы скважины):**
- Хранит название режима работы скважины
- Привязан к филиалу
- Уникальность названия в рамках филиала (с учётом только неудалённых записей)

**SelectionConditions (Условия отбора):**
- Хранит шаблон условий отбора в формате JSON
- Определяет структуру условий (название переменной, единица измерения)
- Привязано к лаборатории и подразделению

**MassFractionOilRefractionTable (Таблица преломления):**
- Хранит соответствия между массовой долей нефти (C) и показателем преломления (n)
- Привязана к методу исследования
- Используется для автоматического расчёта C1 и C2 по n1 и n2 в методе "Массовая доля нефти"

**TestObject (Объект испытаний):**
- Хранит наименование и тег (связь с `sample_type` в методах исследования)
- Содержит область видимости в JSON: `laboratory_ids`, `department_ids`
- Уникальность наименования среди неудалённых записей
- В пробе поле `test_object` хранит наименование из справочника (строка)

**ReportTemplate (Шаблон отчёта):**
- Хранит тип отчёта, версию, файл .xlsx в base64, имя файла
- Привязан к лаборатории и опционально подразделению
- Используется генераторами отчётов ИЛНиНМ

**NdNorm (Норма НД):**
- Наименование нормы и объект испытаний
- Привязка к лаборатории и подразделению
- JSON `method_data`: тексты нормы по id методов исследования

**Role (Роль):**
- Наименование и тип (`laborant`, `engineer`)
- JSON `scopes` — список привязок: `laboratory_id`, опционально `department_id`, матрица прав `permissions` для этой области
- Уникальность пары «наименование + тип» среди неудалённых записей

### Связи между сущностями

- Одна лаборатория может иметь несколько подразделений
- Одно подразделение принадлежит одной лаборатории
- Одна лаборатория может иметь несколько филиалов
- Один филиал принадлежит одной лаборатории и может принадлежать подразделению
- Один филиал может иметь несколько мест отбора проб и режимов работы скважин
- Одно место отбора проб принадлежит одному филиалу
- Один режим работы скважины принадлежит одному филиалу
- Одна проба принадлежит одной лаборатории, может принадлежать подразделению
- Одна проба может иметь несколько расчётов
- Один расчёт принадлежит одной пробе и одному методу исследования
- Один метод исследования может использоваться в нескольких расчётах
- Один метод исследования может входить в несколько групп
- Одна группа методов может содержать несколько методов
- Один протокол может содержать несколько проб
- Одна проба может быть привязана к нескольким протоколам
- Один протокол использует один шаблон протокола
- Один шаблон протокола может использоваться в нескольких протоколах
- Один расчёт может использовать несколько единиц оборудования
- Одно оборудование может использоваться в нескольких расчётах
- Один метод исследования может иметь несколько таблиц преломления
- Одна таблица преломления принадлежит одному методу исследования - массовая доля нефти
- Справочник объектов испытаний не связан внешним ключом с пробами: связь по совпадению наименования и тега

## Безопасность

- Аутентификация через Keycloak с JWT токенами
- Инфраструктура проверки токенов и извлечения пользователя на backend
- CORS настройки для ограничения доступа к API
- Валидация всех входящих данных через Pydantic схемы
- Логирование операций для аудита
- Мягкое удаление записей для сохранения истории
- Матрица прав ролей по привязкам к лабораториям и подразделениям: проверка на UI и API с учётом контекста выбранной лаборатории; пустые `scopes` — нет доступа (кроме admin); страница 403 при отказе в доступе; создание и удаление лабораторий/подразделений — только admin

## Дополнительные функции

### Логирование

Система использует структурированное логирование:
- Логирование всех HTTP запросов с заголовками (опционально, управляется через `LOG_HEADERS`)
- Логирование ошибок валидации
- Логирование операций с базой данных
- Логирование выполнения расчётов с промежуточными результатами
- Логирование генерации протоколов
- Логирование интеграций с внешними API
- Логирование ошибок с полным стеком вызовов
